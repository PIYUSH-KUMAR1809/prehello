# prehello GitHub Action

Comments on every pull request with how much always-on agent context it adds or removes: the CLAUDE.md, AGENTS.md, Cursor rules, skills listings and MCP servers that load before the first message. One comment per PR, updated on every push.

```yaml
# .github/workflows/prehello.yml
name: prehello
on:
  pull_request:
permissions:
  contents: read
  pull-requests: write
jobs:
  context-diff:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
          persist-credentials: false
      - uses: PIYUSH-KUMAR1809/prehello@v1
        with:
          fail-above: 2k   # optional: fail when an agent grows by more than 2,000 tokens
```

`@v1` is a moving major tag (maintainers: `git tag -f v1 vX.Y.Z && git push -f origin v1` after a release). Only full `vX.Y.Z` tags trigger the npm release workflow, so moving `v1` publishes nothing.

The comment looks like:

> **prehello: context before hello**
>
> | Agent | Base | Head | Change |
> |---|---:|---:|---:|
> | `Claude Code` | 6 | 778 | **+772** |

## Inputs

| Input | Default | Meaning |
|---|---|---|
| `path` | `.` | Folder to scan, relative to the repository root (no `..`). |
| `fail-above` | empty | Fail when any agent's always-on estimate grows by more than this (`2000`, `2k`). The comment is posted first. |
| `comment` | `true` | Post/update the sticky comment. The job summary is always written. |
| `version` | empty | An npm version of prehello to run. Empty = build the copy of prehello at the `uses:` ref. |
| `github-token` | `github.token` | Token for the comment. |

Outputs: `delta` (largest change in tokens, signed) and `over-limit` (`true`/`false`).

## What it does

1. Scans the checked-out PR head with an empty `HOME`, so only the repository's own files count (nothing from the runner).
2. Checks out the PR base into a `git worktree` (fetching that one commit if the clone is shallow) and scans it the same way.
3. `prehello diff base.json head.json --markdown` → job summary and one PR comment, found again by its first line `<!-- generated by prehello diff -->`.
4. Fails the check if `fail-above` is exceeded.

prehello only reads files. It never runs anything from the repository, makes no network calls, and starts no processes; git, npm and gh are run by the action's own scripts (`scripts/action/`).

## Fork pull requests and `pull_request_target`

- **Default, safe: `on: pull_request`.** A PR from a fork gets a read-only token, so the comment step prints a warning and the result stays in the job summary. Nothing breaks and no secret is exposed.
- **`on: pull_request_target`** runs with a write token on fork PRs too, so the comment works everywhere. It is risky in general: the workflow has write access while it handles untrusted code. It is only acceptable here if the job does nothing else with the checkout: check out the PR head with `persist-credentials: false`, run this action, and run no build, install or test step on that code. This action itself never executes repository content, and with an empty `version` it builds prehello from the action's own ref, not from the PR. Never combine `pull_request_target` with `uses: ./` (a local copy of this action): the action would then be built from the PR's own code with a write token. If you are unsure, stay on `pull_request`.

## Run the same thing locally

```sh
git worktree add /tmp/base origin/main
npx prehello /tmp/base --save base.json
npx prehello . --save head.json
npx prehello diff base.json head.json            # terminal
npx prehello diff base.json head.json --markdown # PR-comment Markdown
git worktree remove /tmp/base
```

`prehello diff` exits 2 when `--fail-above` is exceeded, 1 on bad input, 0 otherwise. It works on any two saved reports (`--save` or `--json=`), so other CI systems can use it the same way.

## Badge

`prehello --badge badge.json` writes a [shields.io endpoint](https://shields.io/badges/endpoint-badge) file for the agent the card would show:

```json
{"schemaVersion":1,"label":"context before hello","message":"~5.2k tokens (Cursor)","color":"brightgreen"}
```

Commit it (or publish it from CI to a branch or gist) and point shields at its raw URL:

```md
![context before hello](https://img.shields.io/endpoint?url=https://raw.githubusercontent.com/OWNER/REPO/main/badge.json)
```

Colours: under 5k brightgreen, under 15k green, under 30k yellow, under 60k orange, else red. A static badge works too, e.g. `https://img.shields.io/badge/context%20before%20hello-~5k%20tokens-brightgreen`, but it goes stale.
