# Contributing to prehello

Thanks for helping. prehello answers one question: *what does my coding agent load before I say hello, and what could I cut?* Changes
that make that answer more correct, more honest or easier to act on are the most useful.

## Ground rules (these are product promises, not style)

1. **Local and read-only.** No network, no telemetry, no child processes, no API keys. The only writes are output files the user names (all in `src/safe-write.ts`).
2. **Estimates are labelled estimates.** Numbers carry `~` or "estimate"; "at least" marks a lower bound; an item that could not be measured is **never shown as 0**.
3. **No file contents in any output.** File names, plugin/server names and counts only. A line that looks like a secret is reported by line number, never echoed.
4. **Loading rules come from public docs.** If you add or change how an agent loads something, link the doc in `spec/<agent>.json`, set `confidence` honestly (`documented`, `observed`, `assumed`) and say so in the item's notes.

## Setup

```sh
git clone <your fork>
cd prehello
npm ci
npm run typecheck
npm test            # builds, then runs the whole suite (about a minute)
node dist/cli.js --help
```

Node 18, 20 or 22. The suite spawns the built CLI (`dist/cli.js`) in a sandbox with a hermetic `HOME`, so it never reads your real agent config.

## Tests

- Fixtures are generated by `scripts/make-fixtures.mjs` into `test/fixtures/<name>/{home,project}`; add one when you add a behaviour.
- Outputs are checked against goldens in `test/golden/`. After an intended output change run `UPDATE_GOLDEN=1 npx vitest run <file>` and **read the diff** before committing it.
- SARIF is validated against the official 2.1.0 JSON schema (`test/schema/`); keep it valid.
- Add a hostile-input test (`test/hostile-input.test.ts`) for anything that parses untrusted text.
- Windows and macOS behaviour is simulated in the suite and run for real in CI (`.github/workflows/ci.yml`).

## Pull requests

- One topic per PR, with a test. Say what you checked and on which OS.
- Keep dependencies at a minimum: the runtime set is `gpt-tokenizer`, `picomatch`, `smol-toml` (and optional `@resvg/resvg-wasm` for PNG cards). A new runtime dependency needs a good reason.
- Update `CHANGELOG.md` (the "Unreleased" section) and the README if a flag or output changes.
- Please do not paste real prompts, tokens or private config into issues or tests. Use the generated fixtures.
